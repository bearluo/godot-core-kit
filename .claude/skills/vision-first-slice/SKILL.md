# 愿景先行 · 手感切片

做游戏别「系统先行」。这个 skill 只干一件事:让**「我到底想要什么」在写系统之前先变成能看、能玩、能反复改的东西**。否则等系统锁死再铺美术/手感,形状早已错了,结果就是「做出来不是我想要的」。

配套 skill:抛弃式原型用 `prototype`;资源占位落成真文件用 `asset-bank`;真正建系统时用 `developing-core-kit` / `using-core-kit`。

## 病根:不是「代码先于美术」,是「系统先于愿景」

代码先行的真正问题不是美术补得晚,而是**目标体验从没被外化成一个能对照的东西**。你能验证「对不对」(测试门 `FAILS=0`),却从没在早期验证「是不是那种感觉」。当架构本身(程序化占位、drop-in 接缝)允许你**无限期推迟定方向**时,这个坑更深——它让你可以一直不定美术方向、不定手感也照样绿。

修法不是推翻工程严谨,而是在它前面**加两步**:锁愿景、验手感。工程严谨在「找到乐子之后」发力,而不是「代替」找乐子。

## 五阶段(每阶段有交付物 + 门)

### 阶段 0 · 愿景(不写引擎代码,30–90 分钟)

交付物(照 `templates/vision-one-pager.md` 填,落 `docs/vision/`):

- **一句话 X-statement**:「它是 ___,但 ___」。
- **头 30 秒**:玩家第一分钟具体做什么、看到什么、**该感到什么**(情绪词)。
- **情绪板**:3–8 张你在追的游戏截图/美术/参考(丢 `docs/vision/refs/`),逐张说「在追它的什么」;给出配色、形状语言、节奏基调。
  **不能落第三方截图时**(版权、要提交进仓库、要公开分发),用**文字情绪板**代替:
  每条写清「哪个作品的哪一点」+「我追它的什么」,信息量不能比图少。这是正当替代,不是降级——
  但要在 refs 里写明为什么没有图,否则下一个人会以为是漏做了。
- **核心瞬间**:整个游戏最该好玩的那**一个**交互(下一阶段只做它)。
- **反例**:明确「不要变成什么」。

**门**(两条都要过):

1. 能对着这页纸回答「玩家为什么会想再玩一次?」——答不出就别往下走。
2. **这页纸里提到的每个文件路径都真的存在**(`ls` 一遍 `docs/vision/`)。
   实测踩过:一页纸言之凿凿引用 `refs/a.md` `refs/b.md` `refs/c.md`,磁盘上一个都没有——
   内容其实都写在另一个合并文件里,但读的人会以为有三份独立参考。
   这是**文档版的「幽灵 key」**,和 `asset-bank` 查死资源是同一种病:
   **登记与实存解耦,两边都能悄悄不一致**,而且没有任何工具会报错。

**idle / incremental 额外必做**:经济曲线先上电子表格(见 `templates/economy-model.md`)。放置类的「好玩」本质是一条数值曲线;先把产率/成本/倍率/下一个解锁等待时间建出来,**在表里把节奏调爽**,再写引擎代码。别把经济直接写进引擎靠 smoke test 猜——你会看不见曲线。

**cozy / life-sim 额外必做**:情绪板 + 一段「某个清晨的一天」文字走查(时间、光、声音、遇到谁、做了什么、什么让你放松)。氛围是 `FAILS=0` 测不出来的,只能靠对照走查。

### 阶段 1 · 手感切片(抛弃式原型)

只做阶段 0 定的**那一个核心瞬间**,端到端能玩,带上**有意图的**占位(不是最省事的占位):

- 用 `prototype` skill(LOGIC 分支验状态/经济手感;UI 分支并列几版对比)。
- 占位资源要**承载意图**:哪怕粗糙,也要表达目标配色/形状/节奏(用 `asset-bank` 烘焙基线,或手搓)。测的是「愿景」,不只是「机制通不通」。
- 一次性代码,别接 kit、别建目录结构、别写测试。目标是**便宜地反复改到「感觉对了」**。

**门**:自己玩(最好找别人玩)——**「像不像阶段 0 那页纸?」** 不像就在这儿改,别往下。这一步花掉的时间,是在替你省下「建完整套系统才发现不对」的时间。

### 阶段 2 · productionize(这时工程严谨才登场)

切片「感觉对了」后,才用生产流程重建:

- 系统按 `developing-core-kit` / `using-core-kit` 建,走测试门。
- 资源按 `asset-bank`:确定性烘焙出真文件基线 + 按 key drop-in 真/AI 素材。
- 一次性原型代码**扔掉**(按 `prototype` skill 收尾:验证过的决策折进正式代码,原型进 throwaway 分支留档)。

### 阶段 3 · 体验检查点(每个里程碑)

`FAILS=0` 只证明「对」,不证明「是想要的」。但**「玩一遍看看」也不够**——
本 skill 被实测出的最大失效模式是:**体验门靠读代码自评通过**。
有一份自评「体验门通过(example 深度)」的切片,真实画面里标题和「HP / 金币 / 波次」
整行被容器挤出屏幕外,玩家根本看不到血量——而 headless 测试 33 条全绿。

所以体验门要交**三样**东西,缺一不算过。

#### 3.1 真实画面证据(每条结论挂一张图)

规矩:**检查表里每一条回答,必须挂一张截图路径 + 一条任何人可复跑的命令。**
凭读代码得出的结论一律作废。

截图必须**引擎内**产出——非 headless 启动 + `-s` 跑 SceneTree 脚本,进程内落盘:

```gdscript
# test/tools/screenshot.gd —— 非 headless 运行
func _initialize() -> void:
    if DisplayServer.get_name() == "headless":
        quit(2)  # headless 无渲染后端,截不到任何画面
    root.add_child(load(scene_path).instantiate())
    for _i in 90: await process_frame
    await RenderingServer.frame_post_draw
    root.get_texture().get_image().save_png(out_path)
```

四个已踩过的坑:

- ⚠️ **`--headless` 没有渲染后端**,截出来是空的。别在这上面浪费时间。
- ⛔ **禁止 computer-use / 系统截屏 / 操作真实鼠标键盘**:抢占用户外设,而且证据不可复现。
- ⚠️ **窗口会被屏幕尺寸钳制**。要 720×1280 而屏幕装不下时,Godot 会悄悄给你 720×1061,
  文件名却还叫 `1280`。**产出后必须校验 PNG 实际像素 == 声称像素**;装不下就渲进
  `SubViewport` 按真实尺寸出图,并在日志里打印用的哪种模式。
- ⚠️ **短时特效截不到**。0.2 秒的弹道/闪光,随机截一帧大概率什么都没有。
  要证明「看得出谁在打谁」,就画**持续**的瞄准线/目标高亮,而不是只在开火那一帧画。

#### 3.2 体验断言(回归护栏,不是只截一次图)

截图证明「此刻对」,断言才防「以后被改坏」。
**别信「布局问题 headless 测不了」——能测。** 把场景挂进 `SubViewport`,
逐个必看控件查 `get_global_rect()`:

```gdscript
for size in [Vector2i(720,1280), Vector2i(540,960), Vector2i(1152,648)]:
    var sub := SubViewport.new(); sub.size = size
    root.add_child(sub); sub.add_child(load(SCENE).instantiate())
    await process_frame
    for c in must_see_controls:          # 标题/关键状态数值/主视觉区/每个按钮…
        var r := c.get_global_rect()
        assert(r.size.x > 0 and r.size.y > 0)          # 没被压扁
        assert(r.position.x >= 0 and r.position.y >= 0) # 没被推出左/上
        assert(r.end.x <= size.x and r.end.y <= size.y) # 没超出右/下
    # 再查纵向分段互不重叠、主视觉区没被裁
```

这类断言进 `run_all`,分辨率或布局一变就报警。同理可断言:
结算面板开局隐藏 → 局终弹出 → 点「再来一局」回到可玩状态。

#### 3.3 必查清单(这几条最容易「自评通过、实际不成立」)

| 查什么 | 不算数的答法 | 算数的答法 |
|---|---|---|
| 状态可读 | 「脚本里有刷新 `_info.text`」 | 三档分辨率截图里都看得见血量/资源 |
| **有没有「一局」** | 「有失败态」 | 胜利条件 + 失败条件 + 结算 + 「再来一局」入口 |
| **一局多长** | 公式估算 | sim 内累加时钟**实测**,并写成区间断言(如 `300s ≤ t ≤ 480s`) |
| 因果链 | 「伤害计算正确」 | 一张交火图能指出**哪个单位在打哪个**、还差多少 |
| 决策是否成立 | 「看起来有变化」 | **同数量同类型**资源、两种配置、结果显著不同(且无退化样本) |
| 死资源 | 「音效/图都烘焙了」 | 每个 baked key 在产品代码里**真的被调用**(全仓 grep 一遍) |

⚠️ **「决策是否成立」靠对照实验证明,而对照实验有三个坑。** 三个坑长得一样:
**断言写了,却没约束住任何东西**——测试是绿的、代码是对的、结论是假的,
没有任何工具会报错。

**坑一:退化样本。** 「差」的那一组里有个体根本没参与进来(够不着目标、权重为 0、
从未被触发)。这时你证明的是「没参与就没用」,不是「这个变量有讲究」。

只写成原则是拦不住的——**实测两轮、两个模型全都掉进去了**。原则没法执行,**判据可以**:
先定义「这个个体有没有参与进来」的量,再断言**每个个体**都 > 0,而不只是断言两组数量相同。

```gdscript
# 反例:看着像受控实验,其实只约束了「有几个」
assert(good_group.size() == poor_group.size())

# 正例:先断个体有效性,再比结果
for x in good_group + poor_group:
    assert(participation(x) > 0.0, "退化样本 %s 没参与进来,它证明不了什么" % x)
assert(good.metric >= poor.metric + MARGIN)
```

`participation` 换成你这里的名字(覆盖范围 / 命中次数 / 被引用数 / 触发次数……)。
**通用问法:这一组里,有没有哪个个体换成空气,结果完全一样?** 有,就是退化样本。

**坑二:饱和指标。** 拿一个有上下限的量当对照指标,而两边都已经顶到了。
最典型的是「扣光就停」的量(生命、库存、剩余次数)——**两边都失败时它恒等于上限**,
看着在比较,实际零约束。判据:**先问这个量有没有封顶,比较的两边是不是都顶到了。**
顶到了就换一个没饱和的量(撑了多久 / 走到第几步 / 完成度)。

**坑三:跑道不够。** 实验被提前截断,差距还没显出来就收工了。
判据:两组结果贴得很近时,先确认不是截断造成的——放长跑道再看。

⚠️ **修完这三条,要做好差距变小的准备,别回头去凑样本。**
实测:排掉退化样本后,原先「一组全清、一组早早团灭」的漂亮结果直接没了
——那个戏剧性是退化样本造成的,不是被测变量造成的。这时去搜一组能复现原结果的
「差」样本,是**同一种病换个方向**(先有结论再挑样本)。诚实的做法是接受缩小后的真差距,
或按坑三放长跑道让它自己显出来。真差距通常仍然够用——只是不再耸动。

#### 3.4 愿景演进要显式

- 偏了就回阶段 0 改那页纸——愿景可以演进,但要**显式**改,不能默默漂移。
- 演进记录写清四件事:**改了什么 / 为什么 / 代价是放弃了什么 / 哪些不改**。
- 实现与一页纸打架时,先判断**错的是哪一边**——有时自相矛盾的是那页纸本身
  (实测案例:一页纸同时写「顶部晶核」和「怪从上往下冲」,怪从要守的东西那头出发)。
- 最好还是找别人玩,只看不解释,观察卡在哪、何时笑、何时走神。

### 阶段 4 · 从「可玩」到「想再来一局」

阶段 3 的门全是**存在性**的——有没有状态显示、有没有胜负、有没有结算、每个 key 有没有被调用。
它们筛得掉「缺零件」,筛不掉「零件齐全但没味道」。**每项恰好存在、且只是存在**,
玩起来就是实测那句原话:**「基本元素有了,但还不是真正的产品」**——五个门全绿时说的。

更要命的是两头对不上:阶段 0 的门逼你写下情绪词和「再玩一次的理由」,
阶段 3 **一条都不验**。开工前写的东西,验收时没人看。

阶段 4 换一个问法:

> **不测「好不好玩」**(测不了,一测就退化成自评),
> **测「好玩的必要条件里,哪一条是空的」。**

必要条件不成立 → 一定不好玩。全成立 → 不保证好玩,但至少不会是「零件齐但没味道」。

#### 4.1 四条必要条件(通用骨架 + 按类型代入)

| 条件 | 通用问法 | 判据骨架 |
|---|---|---|
| **张力** | 结果曾经悬而未决吗? | 记录**余量**曲线,断言既不全程满、也不单调崩 |
| **能动性** | 喘息的时候有得选吗? | 每个喘息窗口断言**至少存在一个可执行的有意义动作** |
| **可归因** | 输了知道下一次改什么吗? | 结算含**逐步账本** + 指出第一个转折点 |
| **技巧梯度** | 玩得好和玩得差之间有过渡带吗? | 三档打法结果**单调且拉得开**,不是二值 |

```gdscript
# 张力:余量既不能全程顶格(赢得毫无悬念),也不能一路直落(输得莫名其妙)
assert(margin_curve.max() < FULL or threat_count >= 1)
# 能动性:干等 = 空转,不是喘息
for w in breather_windows: assert(has_affordable_move(w))
# 可归因:只报总数等于没报
assert(summary.has("step_log") and summary.first_turning_point > 0)
# 技巧梯度
assert(good.result > mid.result and mid.result > bad.result + MARGIN)
```

**插槽按类型代入**——通用的是问法,变的是「代什么量」:

| 类型 | 余量是什么 | 喘息窗口是什么 | 复玩钩子是什么 |
|---|---|---|---|
| 塔防 / roguelike / 生存 | 生命、**离失败点还差多远** | 波间、房间之间 | 换一套构筑再试 |
| idle / incremental | 距离下一个解锁还要等多久 | 挂机段之间 | 新层数 / 转生 |
| 解谜 / 关卡制 | 剩余尝试、剩余提示 | 关卡之间 | 更优解、更少步数 |
| cozy / life-sim | **不适用**(没有失败态) | 一天里的空闲 | 明天有什么新东西 |

⚠️ **某条在你这个类型不适用时,必须显式写「不适用,因为我的张力来自 X」,不能默默跳过。**
静默省略正是这个 skill 反复栽的同一个形状(幽灵 key / 死资源 / 自评体验门)。
写下「不适用」是一个决定,跳过它是一个漏洞,两者在产出物上长得一模一样。

#### 4.2 三个实测坑

**坑一:选错「余量」的量,会把有张力的过程判成平的。**
实测:塔防拿「生命值」当余量,量出来一整局全程满血 → 判定「毫无悬念」。
可**敌人死在路径 40% 处和死在 95% 处,紧张感天差地别,而两者掉血都是 0**。
生命只在**已经失败之后**才动,它是结果不是过程。
判据:**先问这个量是在过程中连续变化,还是只在出事时才跳。** 只在出事时跳的,
换一个连续量(离终点的距离、剩余时间、完成度、资源缺口)。
⚠️ 换完还要检查它会不会被别的变量污染——同一个塔防里,把防线全堆在入口
也会让「最深推进」显得很浅,那不是没张力,是布局不同。**跨打法比较时尤其小心。**

**坑二:单调不会被调参修好。**
实测:每一波都是同一形状只是更大,于是整局的压力曲线是一条平线;
扫遍 4×4 难度参数网格,**没有一格**能同时满足「会玩的能赢」和「过程中有紧张」——
要么全程碾压,要么突然崩。加了周期性的「重潮」(节奏纹理)之后立刻出现了想要的形状。
判据:**参数网格里找不到好格子时,别继续调参——去看结构里是不是缺纹理。**
线性缩放长不出节奏,节奏得显式做出来。

**坑三:调参依据和回归断言必须是同一个模型。**
量手感要有「模拟玩家」(几档打法各跑完整流程)。这个模型**既是调参依据、又是回归断言**,
两边各写一份就会调 A 测 B——数值调好了测试照样红,或者更糟:测试绿着,
而手感是照另一个模型调的。抽成一份共用代码。
⚠️ 模拟玩家至少要三档:只有极好/极差两端**量不出过渡带**,而真实玩家在中间。
难度要对着中间那档调。

#### 4.3 阶段 0 的情绪词,逐条落到断言

阶段 0 写的每个情绪词和「再玩一次的理由」,阶段 4 都要给出**对应的必要条件 + 判据**。
给不出的,二选一:删掉那个词(承认它只是修辞),或写明「本轮未验证」。
**不允许它既留在一页纸上、又没人验。**

对照着写一张表,一行一个情绪词:

| 一页纸写的 | 结构前提 | 判据 | 结果 |
|---|---|---|---|
| (情绪词) | (哪条必要条件) | (可跑的断言) | 过 / 空 / 不适用 |

## 和旧循环的对照

| 旧(系统先行) | 新(愿景先行) |
|---|---|
| Spec → 建系统 → dogfood → `FAILS=0` → 最后铺美术/手感 | 愿景一页纸 → 手感切片验感觉 → 才建系统 → 每里程碑验体验 |
| 占位「推迟」意图 | 占位「承载」意图 |
| 只有正确性门 | 正确性门 + 体验门(**体验门也要有画面证据和回归断言**) |
| 乐子靠系统建完碰运气 | 先找到乐子,系统为它服务 |
| 门只问「有没有」 | 存在性门(阶段 3)+ **必要条件门(阶段 4)**,后者问「哪一条是空的」 |

## 别人怎么做(参考)

- **MDA 框架**:从 Aesthetics(想要的情绪)倒推 Dynamics→Mechanics。你缺的是 Aesthetics 那一层。
- **手感先行 / juice**(Vlambeer《The art of screenshake》、《Juice it or lose it》):先把一个瞬间做爽。
- **先找玩具**(宫本茂):跳跃在有「游戏」之前先是个好玩的玩具。
- **idle = 电子表格先行**:曲线就是游戏,先在表里调爽。
- **game jam / Amnesia Fortnight**:用一次性原型快速找乐子,再重建。

## 常见错误

| 错误 | 修法 |
|---|---|
| 跳过阶段 0,直接建系统 | 先填那页纸;idle 先建经济表 |
| 占位用最省事的(纯色块/正弦音),不表达意图 | 占位要承载目标配色/形状/节奏 |
| 手感切片就地转成生产代码 | 切片是抛弃式的;验证后重建 |
| 只跑 `FAILS=0` 就以为做完了 | 加体验检查点,找人玩 |
| **读代码自评「体验门通过」** | 每条结论挂截图 + 可复跑命令(3.1) |
| **以为布局问题 headless 测不了** | `SubViewport` + `get_global_rect()` 越界断言(3.2) |
| **把「有失败态」当成「有一局」** | 胜负 + 结算 + 「再来一局」才算闭环(3.3) |
| **局时长靠公式估** | sim 内实测 + 区间断言;估算模型常比实际偏高 |
| **对照实验里放了退化样本** | 断言**每个个体**的参与度 > 0,别只断言两组数量相同(3.3) |
| **拿封顶了的量当对照指标** | 「扣光就停」的量两边都会顶到上限,换个没饱和的量(3.3) |
| 对照差异不明显就下结论「没影响」 | 先确认不是实验被提前截断——放长跑道再看(3.3) |
| 修完对照发现差异变小,回头挑样本凑回来 | 先有结论再挑样本,是同一种病;接受真差距或放长跑道 |
| **一页纸引用了不存在的文件** | 阶段 0 的门 `ls` 一遍;文档也会有「幽灵 key」 |
| 因版权拿不到参考图就跳过情绪板 | 文字情绪板是正当替代,但要写清追什么 + 为什么没图 |
| **截图文件名的分辨率 ≠ 实际像素** | 出图后校验 PNG 尺寸;装不下就渲 `SubViewport` |
| 愿景偷偷漂移 | 要改就显式改那页纸,记清「改了什么/为什么/代价/不改的」 |
| **门全绿但「元素齐了没味道」** | 存在性门筛不出这个;补阶段 4 的必要条件门 |
| **阶段 0 写了情绪词,验收时没人看** | 每个情绪词逐条落到判据,给不出就删词或写明未验证(4.3) |
| **拿只在出事时才跳的量当「余量」** | 生命/库存是结果不是过程,换连续量(4.2 坑一) |
| **参数网格扫不出好格子就继续调参** | 多半是结构缺节奏纹理,不是数值不对(4.2 坑二) |
| 调参用一个玩家模型、测试用另一个 | 抽成一份共用;模拟玩家至少三档,难度对着中间那档调(4.2 坑三) |
| 某条必要条件在本类型不适用就跳过 | 显式写「不适用,因为张力来自 X」;跳过和决定长得一样(4.1) |

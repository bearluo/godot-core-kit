# 愿景先行 · 手感切片

做游戏别「系统先行」。这个 skill 只干一件事:让**「我到底想要什么」在写系统之前先变成能看、能玩、能反复改的东西**。否则等系统锁死再铺美术/手感,形状早已错了,结果就是「做出来不是我想要的」。

配套 skill:抛弃式原型用 `prototype`;资源占位落成真文件用 `asset-bank`;真正建系统时用 `developing-core-kit` / `using-core-kit`。

## 病根:不是「代码先于美术」,是「系统先于愿景」

代码先行的真正问题不是美术补得晚,而是**目标体验从没被外化成一个能对照的东西**。你能验证「对不对」(测试门 `FAILS=0`),却从没在早期验证「是不是那种感觉」。当架构本身(程序化占位、drop-in 接缝)允许你**无限期推迟定方向**时,这个坑更深——它让你可以一直不定美术方向、不定手感也照样绿。

修法不是推翻工程严谨,而是在它前面**加两步**:锁愿景、验手感。工程严谨在「找到乐子之后」发力,而不是「代替」找乐子。

## 四阶段(每阶段有交付物 + 门)

### 阶段 0 · 愿景(不写引擎代码,30–90 分钟)

交付物(照 `templates/vision-one-pager.md` 填,落 `docs/vision/`):

- **一句话 X-statement**:「它是 ___,但 ___」。
- **头 30 秒**:玩家第一分钟具体做什么、看到什么、**该感到什么**(情绪词)。
- **情绪板**:3–8 张你在追的游戏截图/美术/参考(丢 `docs/vision/refs/`),逐张说「在追它的什么」;给出配色、形状语言、节奏基调。
- **核心瞬间**:整个游戏最该好玩的那**一个**交互(下一阶段只做它)。
- **反例**:明确「不要变成什么」。

**门**:能对着这页纸回答「玩家为什么会想再玩一次?」——答不出就别往下走。

**idle / incremental 额外必做**:经济曲线先上电子表格(见 `templates/economy-model.md`)。放置类的「好玩」本质是一条数值曲线;先把产率/成本/倍率/下一个解锁等待时间建出来,**在表里把节奏调爽**,再写引擎代码。别把经济直接写进引擎靠 smoke test 猜——你会看不见曲线。

**cozy / life-sim 额外必做**:情绪板 + 一段「某个清晨的一天」文字走查(时间、光、声音、遇到谁、做了什么、什么让你放松)。氛围是 `FAILS=0` 测不出来的,只能靠对照走查。

### 阶段 1 · 手感切片(抛弃式原型)

只做阶段 0 定的**那一个核心瞬间**,端到端能玩,带上**有意图的**占位(不是最省事的占位):

- 用 `prototype` skill(LOGIC 分支验状态/经济手感;UI 分支并列几版对比)。
- 占位资源要**承载意图**:哪怕粗糙,也要表达目标配色/形状/节奏(用 `asset-bank` 烘焙基线,或手搓)。测的是「愿景」,不只是「机制通不通」。
- 一次性代码,别接 kit、别建目录结构、别写测试。目标是**便宜地反复改到「感觉对了」**。

**门**:自己玩(最好找别人玩)——**「像不像阶段 0 那页纸?」** 不像就在这儿改,别往下。这一步花掉的时间,是在替你省下「建完整套系统才发现不对」的时间。

### 阶段 2 · productionize(这时工程严谨才登场)

切片「感觉对了」后,才用生产流程重建:

- 系统按 `developing-core-kit` / `using-core-kit` 建,走测试门。
- 资源按 `asset-bank`:确定性烘焙出真文件基线 + 按 key drop-in 真/AI 素材。
- 一次性原型代码**扔掉**(按 `prototype` skill 收尾:验证过的决策折进正式代码,原型进 throwaway 分支留档)。

### 阶段 3 · 体验检查点(每个里程碑)

`FAILS=0` 只证明「对」,不证明「是想要的」。每个里程碑加一道:

- 玩一遍,对照阶段 0 那页纸:还像吗?偏了吗?
- 最好找别人玩,只看不解释,观察卡在哪、何时笑、何时走神。
- 偏了就回阶段 0 改那页纸——愿景可以演进,但要**显式**改,不能默默漂移。

## 和旧循环的对照

| 旧(系统先行) | 新(愿景先行) |
|---|---|
| Spec → 建系统 → dogfood → `FAILS=0` → 最后铺美术/手感 | 愿景一页纸 → 手感切片验感觉 → 才建系统 → 每里程碑验体验 |
| 占位「推迟」意图 | 占位「承载」意图 |
| 只有正确性门 | 正确性门 + 体验门 |
| 乐子靠系统建完碰运气 | 先找到乐子,系统为它服务 |

## 别人怎么做(参考)

- **MDA 框架**:从 Aesthetics(想要的情绪)倒推 Dynamics→Mechanics。你缺的是 Aesthetics 那一层。
- **手感先行 / juice**(Vlambeer《The art of screenshake》、《Juice it or lose it》):先把一个瞬间做爽。
- **先找玩具**(宫本茂):跳跃在有「游戏」之前先是个好玩的玩具。
- **idle = 电子表格先行**:曲线就是游戏,先在表里调爽。
- **game jam / Amnesia Fortnight**:用一次性原型快速找乐子,再重建。

## 常见错误

| 错误 | 修法 |
|---|---|
| 跳过阶段 0,直接建系统 | 先填那页纸;idle 先建经济表 |
| 占位用最省事的(纯色块/正弦音),不表达意图 | 占位要承载目标配色/形状/节奏 |
| 手感切片就地转成生产代码 | 切片是抛弃式的;验证后重建 |
| 只跑 `FAILS=0` 就以为做完了 | 加体验检查点,找人玩 |
| 愿景偷偷漂移 | 要改就显式改那页纸 |

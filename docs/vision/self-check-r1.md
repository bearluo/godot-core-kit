## 1. 方法(方法本身是交付物)

采用 **双轨取证**,刻意不用「再跑一遍单元测试」当主证据:

| 轨 | 做法 | 目的 |
|---|---|---|
| **A. 真窗口玩家轨** | `godot --path . res://game/crystal_line/main.tscn` 起 DEBUG 窗口 → `orca computer` 置前/截图/按窗口坐标点击(火塔、格子、重置、尝试「下一波」) | 证明「此刻打开能看见、能点、有反馈」 |
| **B. 场景会话旁证** | 不改 `game/`,新增只读 harness `test/playtest_crystal_line_session_log.gd`:实例化 `main.tscn`,走与玩家相同的 `sim.place_tower` / `start_wave` / `tick` 路径,打印 `SESSION_*` 时间线 | 补全波次/清波/破核等 A 轨截图未钉死的段落 |

**刻意不做的事**: 不改产品代码;不以 `FAILS=0` 当结论;不复述愿景文档当证据。

## 2. 证据清单(轨 A · 真窗口)

窗口: 标题 `晶核防线 (Crystal Line) (DEBUG)`,进程曾在 900×1100 竖长窗运行。

| 文件 | 拍到什么 |
|---|---|
| `02-foreground.png` | 启动画面: 5×8 格、中央裂隙路径、底部红色晶核、底栏「火塔40 / 冰塔45 / 下一波 / 重置」、提示「选塔 → 点路径旁格子。守住晶核。」 |
| `03-after-place-attempt.png` | **点格放塔成功**: 路径左侧橙色火塔(白三角)、提示变为 **「召唤! 笃定落下。」** |
| `04`–`06` / `08`–`10` | 可继续放第二座火塔;资源不足时提示 **「金币不够。」**;底栏按钮始终可见 |
| `01-boot.png` | 对照:未置前时截图被桌面遮挡(方法失效案例,已用置前重采) |

**轨 A 直接证明的玩家能力**

1. 游戏能以独立窗口启动,不是只存在于脚本里。  
2. 单指式操作(点按钮 + 点格子)能落下塔,且文案反馈与愿景核心瞬间用语一致(「笃定」)。  
3. 火/冰按钮有颜色图标区分;路径与可建造格视觉可分;晶核可见。  
4. 无金币时有拒绝反馈,不是静默失败。

**轨 A 未能钉死的段落**

- 多次点击「下一波」后,截图时间轴上**从未出现**路径上的敌怪、也未拍到「第 N 波 / 清波」提示变化(见 `08`/`10` 仍停在放塔或金币提示)。  
- 因此:**「敌潮入场 → 击杀 → 清波松一口气」在真窗口像素层未拿到正面截图。** 可能原因包括:坐标点偏按钮(火塔同 y 可点、下一波未确认命中)、或焦点/遮挡;不能据此断言按钮坏掉,但**也不能声称已用截图证明波次可玩**。

## 3. 证据清单(轨 B · 场景会话日志)

命令:

```text
godot --headless --path . -s res://test/playtest_crystal_line_session_log.gd
```

关键行(完整见 `session-log.txt`):

```text
SESSION_BOOT ... art=baked sfx=baked gold=80 hp=10
SESSION_PLACE1 ok=true gold=40 towers=1 event=placed msg=召唤! 笃定落下。
SESSION_PLACE2 ok=false gold=40 towers=1 event=no_gold   # 冰塔 45 > 剩余 40
SESSION_WAVE_START ok=true wave=1 spawn_left=6
SESSION_COMBAT saw_enemy=true max_enemies=5 waves_cleared=1 gold=62 hp=5 game_over=false last_event=wave_clear
SESSION_DEFEAT game_over=true hp=0 ... last_event=defeat
SESSION_ANTI_MICRO has_player_move_api=false tower_types=fire,ice only
```

**轨 B 证明**

1. `main.tscn` 可实例化;art/sfx 解析为 **baked**(真烘焙文件在跑,不是纯空壳)。  
2. 放塔 → 开波 → **确实刷怪** → 可 `wave_clear`。  
3. 无塔会 `defeat`(破核),「再玩一次」的失败钩子在逻辑上闭合。  
4. 无玩家走位 API;仅火/冰两种塔 —— 符合反例「不要微操 / 不要塔百科」。

**轨 B 的边界**: headless 会话不是人手点屏幕;它证明的是**同一套生产场景逻辑在玩家动作序列下可走完**,不能单独替代「UI 像素层波次」。

## 4. 对照愿景一页纸

### 4.1 已对齐(有证据)

| 愿景句子 | 证据 |
|---|---|
| 竖屏点格子、不吃微操 | 轨 A 截图:底栏大按钮+点格;轨 B `has_player_move_api=false` |
| 头 30 秒:选塔 → 放第一座塔 | `03-after-place-attempt.png` |
| 核心瞬间文案「笃定」落下 | 提示「召唤! 笃定落下。」(轨 A+B) |
| 路径清晰 + 格子决策 | 中央浅色列 vs 侧格;路径格不可放(逻辑+视觉) |
| 2–3 种塔,辨识度 | 火橙三角 / 冰蓝菱形图标+按钮文案 |
| 反例:非 MOBA/非瞄准 | 交互面只有选塔/点格/开波/重置 |

### 4.2 问题清单(严重度 · 现象 · 违反愿景哪句)

#### P1 · 高 · 顶部资源/生命 HUD 在真窗口不可见

- **现象**: 全套轨 A 截图中,**看不到**「晶核 N | 金 N | 波 N」与标题「晶核防线」;棋盘直接顶在窗口客户区上沿。玩家无法在屏幕上读金币与核血,只能靠「金币不够。」事后猜测。  
- **违反**: 愿景「头 30 秒 · 看到什么」隐含的可读状态;以及「资源与站位的小棋感」——**没有可见资源就不成棋**。  
- **说明**: `main.tscn` 里确有 `Title`/`Info` 节点且脚本在刷新 `_info.text`,但 **900×1100 实机画面未呈现**(布局/裁切/拉伸问题待修;本轮不改代码)。

#### P2 · 高 · 真窗口未截到「波次战斗/清波」闭环

- **现象**: 轨 A 未能拍到敌怪与清波反馈;核心瞬间后半句「路径上的怪被打掉 → 晶核安然 + 金币叮」**缺像素证据**。  
- **违反**: 核心瞬间整句;「清波后的松一口气」。  
- **对冲**: 轨 B 证明逻辑层 `saw_enemy` + `wave_clear` 成立 —— **可玩性在逻辑上存在,在 UI 实机演示上本轮未闭合**。

#### P3 · 中 · 开局经济与「两座不同塔」叙事打架

- **现象**: 起始 80 金;火 40、冰 45。放 1 火后剩 40,**买不起冰**(轨 B `no_gold`;轨 A「金币不够。」)。愿景写「2–3 种召唤」。  
- **违反**: 头 30 秒「2–3 种塔」的可及性 —— 第一波前很难同时体验火+冰差异。  
- **连带**: 轨 B 仅 1 火清波时 **hp 10→5**(漏 5 只),「有把握的紧张」偏「几乎破核的惊吓」,且玩家看不见核血(P1)。

#### P4 · 中 · 晶核位置与愿景字面不一致

- **现象**: 实机晶核在路径**底**部(敌从上往下);愿景写「**顶部**血红晶核」。  
- **违反**: 「头 30 秒 · 看到什么」字面。  
- **备注**: 底核更符合常见竖屏 TD;属愿景/实现漂移,体验上未必更差,但**承诺与画面不一致**。

#### P5 · 低 · 缺少「金币跳字」与可听的召唤确认(本轮未测音频设备)

- **现象**: 愿景「金币跳字」;画面无飘字。SFX 源为 baked,本轮 computer-use **未录音频**。  
- **违反**: 头 30 秒「金币跳字」;核心瞬间「清脆召唤音 / 金币叮」在证据链中**未验证听感**。

#### P6 · 低 · 默认编辑器曾停在 `demo.tscn`

- **现象**: 同机 Godot 编辑器标题曾为 `demo.tscn - 晶核防线...`,与 example 主场景 `crystal_line/main.tscn` 并存。  
- **违反**: 不直接违反愿景,但增加「玩家/评审打开编辑器 F5 不一定进塔防」的交付摩擦。  
- **对冲**: `project.godot` 的 `run/main_scene` 指向 `game/crystal_line/main.tscn`;独立 `godot --path . res://game/crystal_line/main.tscn` 可进游戏。

## 5. 结论

**不是「完全不能玩」,也不是「体验门已干净通过」。**

更精确的判断:

1. **能打开、能选塔、能点格放塔、有中文反馈、有路径/核/底栏 —— 轨 A 像素证据充分。** 真实玩家「此刻」可以开始构筑。  
2. **波次战斗与清波在逻辑层成立(轨 B),但本轮真窗口截图未能闭合该段证据 —— 核心瞬间后半截不能仅凭本报告宣称「UI 上已玩爽」。**  
3. **P1(HUD 不可见)是实机体验的关键缺口**:它直接削弱愿景承诺的「小棋感」与「有把握」,并让 P3 的经济挫败更难读。  
4. 此前 `experience-checkpoint.md` 的「体验门通过(example 深度)」在 **放塔反馈/反微操** 上仍站得住,在 **状态可读性与完整核心瞬间的像素证明** 上被本轮证据**降级** —— 建议下一轮先修 HUD/布局再做人手或自动化 UI 波次验收。

### 一句话给协调者

**《晶核防线》真窗口可启动且放塔核心手感有截图;波次闭环靠场景会话日志旁证而非战斗截图;最大实机问题是资源/核血 HUD 看不见,与愿景「小棋感」冲突。**
